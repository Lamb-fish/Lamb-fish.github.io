TLCP 抓包分析与解密

发表于11月17日|更新于11月17日|国密TLCP
|浏览量:

一、识别协议

快速判断：

  1. 记录层版本是否为 0x0101？

  2. 密码套件是否 0xE0xx？

  3. Certificate 是否包含两本实体证书（签名 + 加密）？

  4. 握手消息是否符合 TLCP 的顺序？

如果以上都满足，基本可以确定是 TLCP。注意：

  • 标准 TLS 1.0/1.1/1.2 的版本号是 0x0301/0x0302/0x0303；0x0101 基本就是 TLCP/自定义协议；

  • TLS 1.2/1.3 的版本号通常是 0x0303；

  • 某些网关可能使用自定义封装，需看原始字节。

二、读 ServerHello 套件

ServerHello 中读取套件代码，字段顺序如下：

套件 → 密钥交换：

  • 0xE011 / 0xE051 → ECDHE

  • 0xE013 / 0xE053 → ECC

工具：

  • Wireshark：tls.handshake.ciphersuite

  • tshark：tshark -r x.pcap -Y "tls.handshake.type == 2" -T fields -e tls.handshake.ciphersuite

三、判断认证方式

按以下步骤查找消息：

  1. 过滤 tls.handshake.type == 13，看是否有 CertificateRequest。

  2. 过滤 tls.handshake.type == 11，看客户端是否发送 Certificate。

  3. 过滤 tls.handshake.type == 15，看是否有 CertificateVerify。

结论：

  • 有 CertificateRequest + 客户端 Certificate + CertificateVerify → 双向认证。

  • 只有服务端 Certificate → 单向认证。

  • 如果需要整个消息体，保留 2 字节长度。

  • 注意区分记录头、握手头、字段长度。

六、解密静态 ECC 会话

前提是拿到服务端加密证书的私钥。

步骤：

  1. 从 ClientKeyExchange 解析出 C1、C3、C2。

  2. SM2 解密得到 48 字节预主密钥。

  3. 用 client_random、server_random 派生主密钥。

  4. 派生 key_block。

  5. 解密记录层，校验 Finished。

ECDHE 为什么不能只靠 pcap 解密：

  • 预主密钥由临时私钥协商，pcap 里只有临时公钥。

  • 需要服务端/客户端的临时私钥，或 keylog（如果实现支持导出）。

  • 即使有静态加密私钥，也不能直接解出 ECDHE 的预主密钥。

问题 表现 处理
TCP 重组/分片 单帧看不到完整握手 用 Wireshark 的 TCP 重组或 Follow TCP Stream
